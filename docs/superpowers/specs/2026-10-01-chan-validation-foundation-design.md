# 缠论升级第一阶段：数据与逐根回放验证底座

日期：2026-10-01

状态：用户于 2026-10-01 确认设计及实现计划；第一阶段实现、252项回归、有界实测和独立审查后的修复已完成。实现提交 `6c9dbfb` 已按用户选择合并到本地 `main`，用户随后授权完成远端同步与收尾，未重启用户服务。验收记录见 [离线验证工具](../../chan-validation.md)。

开发前稳定基线：`67a0b99d100de924a9e41a2ef9ee195a6afadcd4`，已先行推送到 `JeffreyCaicai/tongdaxin-stock` 的 `main`。基线的全部单元与前端运行时测试为200项通过；第一阶段完成后为252项通过。测试通过不代表预测能力已经验证。

## 1. 目标与边界

用户希望减少缠论分析误报，并能判断升级是否真正改善预测效果。系统继续只做个人股票研究、观察和模拟验证，不自动交易，不改动关注名单、持仓数量或成本。

整体方向分为三个可独立验收的阶段：

1. 数据与验证底座：分钟时间正确、输入可复现、旧模型能逐根回放。本设计只详细规定这一阶段。
2. 结构升级：评估公开缠论引擎，增加线段、中枢和多周期确认；以实验版本与旧模型并行。
3. 有效性验证：固定研究方案，滚动样本外比较、模拟成本和成交约束、分组稳定性检验，再决定是否替换现有模型。

不把同意整体方向解释为已确认新模型有效。本阶段不引入新买卖规则，不调参追求历史胜率，不恢复原来的交易栏或 MA 回测栏目。

## 2. 设计时已核实的现状

- `chan_analysis.py` 的 `daily_pen_overlap_v2` 仅接受完成日线，按分型、笔、三笔重叠区给出候选；不是完整递归缠论。其数据质量门槛及已实现的确认日期保持不变。
- 官方 K 线请求为 `TdxShare.PBFXT`，当前 `TQFlag=11`，单次最多请求 1000 根，固定 `Startxh=0`。不能因此声称有多年分钟历史或已知复权口径。
- `_tdx_official_date_text` 丢弃分钟时间；`market_klines` 以证券、源、周期、`trade_date` 唯一。如果分钟线只保留日期，同日多根会覆盖。
- `opportunity_tracking.py` 是推荐名单的后续价格观察，不是缠论信号的专属回放，也没有费用及可成交验证。继续保留原用途，不混入新统计。
- 原 `backtest.py` 是 MA/成交量规则，不能拿它的结果作为缠论效果证明。

### 本轮只读数据探查

对 `600519` 分别请求 12 根日线、60 分钟线和 5 分钟线，三个请求均成功返回 12 根。本次直接调用现有数据提供器的请求函数，没有经过写缓存 API，没有写数据库。

| 周期 | 实际返回的末端时间字段示例 |
| --- | --- |
| 日线 | `Item[0]="20260930"`, `Item[1]="0"` |
| 60 分钟 | 日期 `20260930`；时间 `41400, 50400, 54000` |
| 5 分钟 | 日期 `20260930`；时间 `53400, 53700, 54000` |

这些时间值符合当日秒数编码，分别可还原为 11:30、14:00、15:00 及 14:50、14:55、15:00。本次证实的是该股票、该参数和该时刻能返回分钟数据；没有证明所有证券权限、最大历史深度、分页能力、复权语义或实时更新稳定性。

## 3. 方案选择

| 方案 | 优点 | 局限 | 决定 |
| --- | --- | --- | --- |
| 直接给当前笔级模型增加条件 | 改动较少 | 难以区分真实改善和历史拟合 | 不作为本轮起点 |
| 立即重写完整缠论系统 | 可定制规则 | 数据和验证缺口仍在，无法证明替换合理 | 暂不采用 |
| 冻结基线，先建立数据与回放底座 | 能复现当时可见结果，为引擎替换提供同口径比较 | 第一阶段不会立即增加预测能力 | 采用 |

后续引擎优先评估 `chan.py` 公开源码的可运行部分，核对许可证、版本、规则和测试后再决定是否接入。多周期时间尺度不自动等于严格的递归走势级别，不能仅凭两个周期同向就标为确认买卖点。

## 4. 时间与价格数据契约

### 4.1 时间标准化

- 现有日线 `trade_date=YYYY-MM-DD` 保持兼容，不批量重写日线历史。
- 分钟线的 `trade_date` 作为现有缓存键，使用完整、固定格式的上海时区时间戳，例如 `2026-09-30T15:00:00+08:00`；新增明确的 `session_date` 与 `bar_end_at` 元数据，随缓存 payload 保留并在 API 输出，避免调用方把时间键误当日期。
- 新研究入口只接受 `daily`、`5min`、`60min` 及相应已核查别名；未知周期明确拒绝。现有行情接口的其他周期不因此改写为日线或静默删除，未核实的周期不进入验证数据集。
- 官方位置数组同时读取日期与独立的时间字段。字段缺失、编码冲突、无效日期、时间越界或不符合该周期交易时段时标为不可用，不推测当天最后一根时间。
- 原始字段含义需用完整会话样本与受信的接口资料交叉核对。时间编码、周期起止含义及边界测试未通过前，不将该周期用于确认信号。
- 只向分析器提供在本次 `as_of` 前已结束的 K 线；上海午间休市不补造 K 线。收盘时间和供应商实际发布时间分别记录，不能用请求时间冒充历史可见时间。

### 4.2 缓存兼容与完整性

- 同日不同分钟有不同缓存键；同一时刻重复响应应幂等。
- 历史分钟缓存中只有日期、无法恢复时分的记录保留但不用于新分析。不得为它们伪造时刻；重新拉取后才获得可用输入。
- 读取分钟缓存时按完整时间排序，过滤旧格式，不让最新缓存替换本次响应的日期范围。
- 规范周期名必须在请求、缓存读写和输出三处一致，避免 `60m` 与 `60min` 分开形成相互矛盾的历史。
- 验证有限正数 OHLC、最高最低关系、重复时间、冲突价格、停牌及缺口。重复且一致可去重；同时间价格冲突保留质量错误。

### 4.3 历史范围与复权

- 每批记录源、周期、请求偏移、数量、抓取时间、价格口径参数、解析器版本、实际首尾时间、质量问题及是否截断。
- 先只读验证历史分页的次序、跨页重叠和边界；通过后才允许增加历史深度，设定明确的请求上限、失败退出和限流策略。
- 历史不足、分页不支持或 Token 权限不足必须明确报告，不能静默换源、补假数据或假装完成多年验证。
- `TQFlag=11` 只是已记录的参数，不是已核实的复权定义。复权语义、分红和供应商历史修订未验证前，只能标为历史重建研究，不能声称恢复了历史真实可交易价格。
- 多次获取的历史可能被修订。保存旧输入快照并另建新版本，不覆盖曾用于验证的数据。

## 5. 可复现输入快照

验证输入使用独立本地 JSON 数据集及清单，存放于 Git 已忽略的 `data/cache/chan_validation/`，不提交到 GitHub。快照和回放模块不读取或保存 Token、Cookie、请求头、账户数据，也不需要持仓成本；联网采集的认证仍仅由现有数据提供器处理。

清单包含：数据集版本、证券范围与选择日期、来源和价格参数、每个周期的首尾范围、数据哈希、生成时间、质量结果。证券集合来自调用方明确指定的研究样本，不能因为后来上涨而补选。

运行以只读方式使用已固定的数据集，回放过程中禁止联网、刷新缓存或读取后来改变的市场状态。相同输入、模型版本、配置和截止时间必须生成相同事件及数值结果；运行编号和实际执行时间可作为独立元数据变化。

最初的样本可以来自个人关注股，但报告必须标为选定样本研究，不能推广为全市场结论。没有历史时点证券名单及退市数据时，明确存在选择与幸存者偏差。

## 6. 逐根回放与事件记录

### 6.1 回放规则

- 第一阶段仅回放冻结的日线 `daily_pen_overlap_v2`；分钟线先完成数据验收，不提前混入现有模型。
- 从满足原模型最小输入长度的位置开始，逐个历史收盘时点调用分析器。输入只能是该时点及之前的 K 线，`as_of` 使用该历史时点，不使用电脑今天的时间。
- 不先对整段数据画完笔和中枢再回填历史信号。任何引用未来确认数据的事件都应被测试阻断。
- 固定基线的模型版本、配置及源码指纹。共享函数后来修改时，不允许沿用同一基线名称继续产生不同结论。
- 对实时分析和历史回放采用同一输入契约；历史重建可证明无未来 K 线泄漏，但不能证明供应商当时返回的数据与今天下载的历史完全一致。

### 6.2 事件字段与状态

每个事件记录证券、模型、规则配置、结构锚点、数据集哈希、首次观察时间、规则确认时间、结构端点时间、支持证据、价格基准、失效条件及质量状态。

必须区分：

- `candidate`：旧模型的疑似三买或疑似三卖。不得改名为已确认。
- `rule_confirmed`：为后续经过验证的规则保留，第一阶段基线不得产生此状态。
- `invalidated`：可追溯的明确失效条件被触发。
- `withdrawn`：后来计算不再出现该候选，但没有足够证据认定指定失效条件已触发。
- `data_unavailable`：数据不足或质量问题导致无法继续判断，不等同于成功、失败或结构失效。

首次出现的记录保持不变，后续变化追加为新事件；不能因图形后来重画就删除旧提示。结构端点时间和当时首次可确认时间分开显示，禁止把后者回填为前者。

基线观察采用明确的收盘失效口径：三买候选后续已完成日线收盘价不高于首次候选的中枢上缘，三卖候选收盘价不低于首次候选的中枢下缘，分别记为失效。冻结首次边界，不因后来中枢变化追溯改写；这只是候选跟踪条件，不是成交或止损模拟。仅盘中触及边界另记风险证据，不冒充已收盘失效。

同一结构持续存在多天只形成一个观察机会，后续日作为状态更新。结构延伸保留其初始锚点；真正形成新结构或失效后出现新的独立条件才产生新机会。重复运行同一数据集不能重复累计统计样本。

## 7. 第一阶段验证输出

第一阶段先验证旧模型，而不是展示未经产生的性能改进。提供本地研究入口和可导出的 JSON 报告，不向现有界面增加第二套交易面板。

报告包含输入范围、质量与覆盖、逐时点结果、候选首次出现及后续状态、规则版本和完整事件明细。可按明确截止时间复现某只股票当时的图形与结论。

附带 5、20、60 个交易日的价格观察，20 日作为预先指定的主要周期：

- 起点为候选可见之后的下一有效交易日开盘，终点为第 N 个交易日收盘；不能用事后转折点价格代替起点。
- 使用正确标识的 `SH000300` 日期范围，同时检查个股是否有对应有效数据。基准缺日、个股停牌、窗口不完整或数据口径无法验证时明确不可评估，不向前移动窗口凑数。
- 日历作为固定输入保存来源、版本和范围，并与沪深300日期交叉检查。没有经核实的交易日历时，无法排除指数接口漏日，结果标为 `unverified_calendar`，不把数出的 N 根 K 线直接宣称为 N 个实际交易日。
- 未到期为 `pending`，质量失败为 `unavailable`，与成熟有效样本分开，缺失价格不转换为零。
- 输出价格收益、同期基准超额及逐日收盘路径回撤。上涨候选与下跌候选分组展示，负向候选不假设可做空，也不转换成持仓盈利。
- 本阶段统计是价格观察，不是可执行盈亏。费用、滑点、涨跌停成交约束和现金分红尚未模拟，报告必须列明，不能显示成本后胜率。
- 不把多只股票同日、同股重复提示和重叠窗口当成独立试验。第一阶段不输出预测概率、显著性结论或已校准胜率。

后续阶段才比较旧模型与新模型：按时间滚动划分研究及检验区间，对重叠标签隔离，记录所有参数尝试，使用适合相关样本的区间估计。新增过滤逐项对照，避免把减少信号数量当成提高有效性。扩大样本、成本及可成交验证完成前，不升级产品中的可信度标签。

## 8. 模块边界

| 模块 | 第一阶段责任 |
| --- | --- |
| `market_data.py` 及独立时间解析助手 | 官方分钟日期和时间解码、周期规范化、数据质量与来源元数据 |
| `repository.py` / K 线输出 schema / 现有 K 线 API | 分钟唯一键、旧缓存隔离、时间字段兼容；日线契约不变 |
| 独立数据集模块 | 快照、清单、哈希和固定输入校验，不持有凭证 |
| 独立缠论回放模块 | 只接受固定输入与分析器，逐根重放，追加事件 |
| 独立观察评价模块 | 相同日历下的 5/20/60 日结果、缺失状态和重复样本标识 |
| 本地研究入口及测试 | 明确指定输入、输出位置和截止时间；不改动持仓或现有模型选择 |

不直接复用推荐跟踪任务表保存缠论事件，不把新逻辑继续堆入 `main.py` 或 `static_ui.py`。本阶段不引入常驻调度器、不做自动扫描、不新增外部服务。

## 9. 验收标准

1. 一天的多根分钟 K 线在解析、缓存、API 往返后数量和时分均保留；日线 API 和旧报告保持兼容。
2. 5/60 分钟跨日、午间休市、未完成 K 线、缺失时刻、异常秒数、重复响应和周期别名都有回归测试。
3. 旧的日期级分钟缓存不会进入新计算，也不会被未经许可的清理操作删除。
4. 构造包含未来大涨或下跌的数据；添加未来 K 线不得改变此前已经写出的事件。结构确认不得早于所依赖 K 线的可见时点。
5. 每个前缀的回放结果与该前缀的单独分析一致；同一快照重复运行得到相同事件内容及观察数值。
6. 中枢延伸、候选消失、失效、缺数和历史修订不覆盖首次提示；连续同一候选不重复计数。
7. 结果覆盖未到期、停牌缺日、基准缺漏、零成交量、历史不足、复权未验证和无候选。无候选是正常研究结果。
8. 运行研究不会修改持仓、关注、推荐快照及旧分析报告；报告及日志不存在凭证。
9. 完整现有测试继续通过；真实分钟数据另做有界、只读实测，并分别报告接口可用性、数据深度和未验证项目。

## 10. 发布与后续准入

`main` 保留已推送基线，新工作在 `codex/chan-validation-foundation`。设计确认后编写可执行实现计划，再进入测试驱动开发。新增实现验收前不重启用户服务替换现有模型。

第一阶段通过只意味着有了可信的测试工具和更完整的数据输入，不意味着缠论更有效。第二阶段引擎采用固定公开版本，先对照运行；第三阶段以扣除模拟成本后的样本外收益、风险、信号覆盖和确认延迟共同判断是否有改进。结果没有优势或证据不足时，继续标为实验性分析，不强制替换现有模型。
